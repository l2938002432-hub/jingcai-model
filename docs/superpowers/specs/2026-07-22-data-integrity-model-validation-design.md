# 竞彩模型数据完整性与独立验收设计

## 目标

在不降低现有验收门槛的前提下，修复 MLS 历史比赛日期污染，扩充欧冠资格赛训练基础，并提高每日推送的容错性。任何联赛只有在未参与调参的时间锁箱上同时达到 Log Loss 与 Brier 改善至少 1%，才允许从未批准状态进入 `PAPER_ONLY` 推荐池。概率验收不等同于盈利证明；真实 ROI 必须另用带时间戳的历史竞彩固定奖验收。

## 范围

本阶段包括：MLS 日期交叉校正、统一时间字段、MLS 时间衰减模型与冻结集成、欧冠资格赛多赛季及跨联赛实力先验、通知通道失败隔离和每日幂等。不包括自动投注、降低验收阈值、使用锁箱反复调参或承诺盈利。

## 数据完整性

### MLS

现有 USA 历史数据存在日/月混排，旧的 250 场锁箱及其 0.86%/1.03% 结果标记为无效待重验。不得用简单的全量月日交换修复混合格式。校正器使用独立可信赛程源，以赛季、主客队、90 分钟比分进行匹配；只有唯一匹配时才接受日期。冲突、重复或无法唯一确认的记录进入隔离报告并从训练、校准和锁箱中排除。

修复后按时间重新划分开发集、校准集和全新锁箱。旧锁箱可用于开发，但不得再次作为最终证据。

### 欧冠资格赛

将 OpenFootball 欧冠资格赛扩展到至少 8 个、目标 10 个完整赛季。解析结果保留比赛日期、来源时刻、国家或协会、轮次、对阵组标识、首回合/次回合和开赛前已知的首回合净胜球。来源没有时区时不得标为精确 UTC；日期级排序使用显式的 `kickoff_date`，精确时刻另存并注明来源时区状态。

球队标识通过可审计别名映射统一。无法确定的球队不做猜测性合并。

## 模型设计

### 统一时间接口

模型排序统一识别 `kickoff_utc`、`kickoff_date`、`kickoff`、`date` 和 `timestamp`，并在入口处规范化。时间缺失、倒序或同一比赛重复时失败关闭。所有滚动特征都有 `as_of` 截止时间，禁止读取比赛开赛后的信息。

### MLS 候选模型

在较早开发集上比较时间衰减 Dixon–Coles、现有 Elo，以及两者的固定权重集成。时间衰减半衰期只允许在预先声明的小网格中选择；球队样本不足时收缩到联赛均值。概率校准只使用锁箱之前的校准集。

模型、半衰期、集成权重和校准参数冻结后，仅运行一次全新时间锁箱。不得根据锁箱结果再次选择参数。

### 欧冠资格赛候选模型

资格赛自身样本稀疏，核心输入为比赛截止日前由国内联赛和既往欧战联合更新的全球 Club Elo。新球队初始值收缩到所属联赛或协会层级均值。可加入比赛时点之前已公布的 UEFA 俱乐部/协会系数，并记录发布日期。预测层加入主场、轮次、首/次回合和次回合开赛前已知的首回合比分。

## 验收

MLS 使用重新建立的连续最新时间锁箱。欧冠资格赛使用最新连续两个赛季锁箱，较早赛季开发，中间赛季校准。欧冠两回合相关性通过按对阵组聚类的 bootstrap 计算区间。

必须同时满足：

- 相对预先声明基准的 Log Loss 改善至少 1%；
- Brier Score 改善至少 1%；
- 聚类置信区间不显示明显劣化；
- 校准斜率、ECE 和新参赛队子组没有不可接受的恶化；
- 数据审计无未解释的时间倒序、重复比赛或未来信息。

未通过时保持未批准，不进入每日推荐池。只有获取真实、带采集时间的历史竞彩固定奖后，才单独验收 ROI、最大回撤、命中率和收益置信区间。

## 推送可靠性

飞书、Server酱和企业微信逐通道独立执行并汇总结果；单个通道失败不阻断其余通道。生产运行要求至少配置一个通道。每日通知使用日期、报告哈希和环境生成幂等键，云端与本机后备节点不得重复发送同一报告。

正式部署前轮换已出现在截图中的飞书 Webhook 和 Server酱 SendKey，只将新值保存到本机忽略文件与 GitHub Secrets，严禁进入日志、报告或 Git。

## 测试与交付顺序

1. 增加日期污染回归样例、时间字段排序和失败关闭测试。
2. 实现 MLS 交叉校正并生成隔离报告。
3. 建立冻结开发/校准/锁箱清单，再实现并比较候选模型。
4. 扩展欧冠资格赛多赛季解析和跨联赛先验，执行聚类锁箱验收。
5. 实现通知失败隔离、至少一通道检查和幂等测试。
6. 全量测试通过后同步正式项目并提交 Git；验证报告明确记录数据版本、参数冻结点和未通过原因。

## 失败处理

外部数据不可用、日期无法唯一确认、时区不明、球队映射冲突、锁箱清单变化或通知全部失败时，任务应失败关闭并留下不含密钥的诊断信息。系统不得用缺失值静默生成正式推荐。
