# 全量当日竞彩赛事覆盖设计

## 目标

系统先读取官方全部在售足球比赛，再对每场给出明确状态。赛事是否展示不再由联赛白名单决定；白名单只影响候选推荐的可信度。

## 范围

- 每日比赛页必须显示官方在售比赛的 100%。
- 每场输出中文主客队、赛事、开赛时间、五玩法赔率、数据状态、可信度与原因。
- 候选页只显示经严格条件筛出的 `候选决策` 比赛。
- 不使用未验证历史奖金宣称盈利；模型状态仍为 `PAPER_ONLY`。

## 单场状态

| 状态 | 含义 | 能否进入候选 |
|---|---|---|
| 候选决策 | 数据完整、赔率新鲜、通用概率可用、保守 EV 为正且风险检查通过 | 可以，仍仅模拟 |
| 研究观察 | 可计算通用概率，但赛事尚无独立时间锁箱验收 | 不可以 |
| 数据不足 | 缺球队映射、历史、赛程或必要玩法数据 | 不可以 |
| 安全拒绝 | 赔率过期、停售/开赛已过、数据冲突或上游异常 | 不可以 |

## 模型与数据流

1. 官方在售快照是当天比赛池的唯一入口，任何比赛都必须保留在报告中。
2. 对每场先执行新鲜度、开赛与字段完整性检查。
3. 已有本赛事历史时使用赛前 Dixon–Coles 概率；缺少本赛事历史时使用跨联赛 Elo/近期赛果基础概率，且状态最多为 `研究观察`。
4. 赛事级验收配置从“是否展示”改为“是否允许候选”。只有通过时间锁箱概率验收的赛事与玩法，才可在通用概率、赔率与风控都通过后进入候选。
5. 每日报告汇总：官方在售、可计算、候选决策、研究观察、数据不足、安全拒绝及按原因的数量。

## 融合的工程模式

- **统一赛事池**：参考多联赛预测工具的做法，先形成按官方比赛编号去重的当日比赛池，再把数据、概率和候选判断附加到同一场比赛上。
- **提供器分层**：赛程/官方奖金、历史赛果、跨联赛 Elo 和赔率快照各自独立。任一非官方补充源不可用时，比赛仍展示并说明缺口；官方奖金是进入候选的必要条件。
- **模型分层**：通用跨联赛概率仅用于研究观察；赛事级时间锁箱验收是候选决策的额外闸门。不得用通用模型绕过未验证赛事的候选限制。
- **可观测性**：每个数据字段记录来源与时间；日报输出覆盖计数和缺失原因。快照过期时保留赛事池但统一标注安全拒绝。
- **验证分层**：训练、时间顺序验证、赔率/EV 筛选和赛前冻结账本分别保存，避免把回测、研究概率和真实收益混为一谈。

## 验收

- 给定包含未验证赛事的官方快照，日报仍显示所有赛事。
- 未验证赛事只能为 `研究观察`/`数据不足`，绝不进入候选。
- 已验证赛事仍需赔率新鲜、未过停售时间、保守 EV 为正才可进入候选。
- 数据过期时所有赛事标记 `安全拒绝`，日报不生成候选。
- 单元测试覆盖上述状态转换；现有 ROI 和赛前冻结保护测试继续通过。

## 非目标

- 不自动下注。
- 不把研究观察显示为投注建议。
- 不以第三方或赛后赔率宣称中国竞彩 ROI。
