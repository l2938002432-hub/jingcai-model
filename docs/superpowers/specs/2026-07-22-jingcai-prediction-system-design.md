# 竞彩预测与盈利推荐系统设计

- 日期：2026-07-22
- 状态：已完成分节讨论，待用户复核书面规范
- 正式项目目录：`D:\Codex-Workspace\03_Projects\P003_JingCaiModel`
- 设计目标：在可控回撤与严格数据时点约束下，提高足球竞彩概率预测质量，并从已验证玩法中选择保守预期净利润最高的当日组合。

## 1. 边界与成功定义

系统每天分析中国竞彩网当日受注足球比赛，计算胜平负、让球胜平负、比分、总进球和半全场概率，比较官方固定奖金，输出网页、命令行报告及飞书/微信通知。

系统不保证中奖或稳定盈利，不自动购票，不为了“每天必须有推荐”而输出负期望候选。盈利最优决策可以是当天不下注。

主目标不是命中率，而是在风险约束下最大化保守预期净利润：

`保守 EV = 概率下界 × 实际可投注奖金 - 1 - 数据与模型安全垫`

系统同时约束最大回撤、单场和单日暴露、同场相关玩法、最长连败及数据质量。

## 2. 已批准的运行方案

采用 A+C 双运行器：

- A 云端主运行器：GitHub 私有仓库和 GitHub Actions 定时运行；生成脱敏静态报告并发布至 EdgeOne Pages；飞书为主推送，微信为辅助推送。
- C 本地备用：同一套 Python CLI 可由 Windows 定时任务或人工命令运行；本地 Streamlit 页面查看结果。
- 云端任务延迟或访问国内数据源失败时，允许幂等重试、手动补跑和本地接管。
- 不绑定付费服务。免费平台额度、条款或连通性变化时，运行器可以替换而不改动领域模型。

个人微信没有稳定的官方机器人接口。首选企业微信群机器人；若用户不使用企业微信，则以 Server酱作为辅助渠道，飞书机器人作为正式主通道。

## 3. 数据设计

### 3.1 权威口径

- 中国竞彩网 `sporttery.cn` 是受注赛事、玩法开售状态、让球值、固定奖金和赛果的唯一权威口径。
- 球探体育、雷速体育仅作人工交叉核验，不依赖私人接口、登录 Cookie 或高频抓取。
- 官方没有面向公众承诺稳定性的正式 API，因此采集器必须低频、限速、缓存、保存原始快照，并提供人工导入兜底。

### 3.2 免费辅助数据

- Football-Data.co.uk：历史结果、比赛统计和多庄家历史赔率，用于离线训练与回测。
- StatsBomb Open Data：有限赛事的事件、阵容和 xG，用于特征研究，不能承担每日全覆盖。
- football-data.org 免费额度：基础赛程与结果校验。
- Open-Meteo：球场时点天气。
- 俱乐部、联赛官网与官方发布：重要伤停和阵容的一手确认。

每个数据源都通过独立 `provider_adapter` 接入。统一记录 `provider`、`retrieved_at`、`event_time`、`as_of`、原始快照哈希、许可版本和质量标记。

### 3.3 赛事映射与时点

国际比赛与竞彩场次采用赛事、开赛时间、主客队别名三重匹配；禁止仅靠模糊队名自动合并。改期、取消、时区和 90 分钟赛果口径必须显式处理。

奖金、伤停、预计阵容、天气和所有滚动特征必须早于对应竞彩停售时间。停售后公布的首发只用于赛后解释，不得回填预测或回测。首发未确认时扩大概率误差、提高安全垫或取消推荐。

## 4. 模型架构

### 4.1 统一概率底座

初版使用：

- 带时间衰减的 Dixon–Coles 进球模型，产生主客队全场比分联合概率矩阵。
- 动态 Elo，处理升降级、新队和近期实力变化。
- 官方奖金去水后的市场概率，作为强基线和集成输入。
- 概率校准层，按时间上更晚且与训练分离的数据拟合。

全场比分矩阵统一推导胜平负、让球胜平负、比分和总进球，避免不同玩法的概率互相矛盾。

半全场采用独立的半场进球率和半场—全场条件状态联合模型，输出胜胜、胜平、胜负、平胜、平平、平负、负胜、负平、负负九类概率；禁止将半场和全场边际概率简单相乘。

### 4.2 后续模型

LightGBM、XGBoost 或 CatBoost 只能在严格时间外验证中证明增益后加入，优先用于预测结构模型残差或学习集成权重。候选特征包括可靠的赛前 xG、射门、赛程密度、休息时间、天气、伤停和赔率变化。

任何新特征或模型都必须执行消融实验。若只提高训练期或单一联赛 ROI，不进入正式模型。

## 5. 历史训练、经验总结与持续学习

历史数据承担模型训练和主要盈利验证，不等待长周期实时积累：

1. 按比赛时间建立训练、校准、测试窗口。
2. 使用过去多个赛季训练，预测随后月份或轮次，然后窗口前滚。
3. 保留最近一个完整时段作为最终盲测集，在所有模型和阈值冻结前不得查看。
4. 每次预测保存不可修改记录：数据快照、特征 `as_of`、模型版本、概率、候选、奖金和 Git SHA。
5. 赛后自动结算，按联赛、玩法、赔率区间、置信度、是否缺阵和时间段汇总误差。
6. 生成“历史经验报告”：识别持续偏差、失效特征、适用联赛、赔率区间和玩法，不把个别爆冷或短期连胜当规律。
7. 候选改进必须在新的时间外窗口复验；晋级后保留旧模型以便回滚。

经验沉淀使用结构化实验注册表，记录假设、数据截止时间、特征、模型、超参数、推荐阈值、基线、预期方向、验收条件、结果和最终决定。失败实验同样保留，防止重复挖掘已经证伪的噪声。历史经验不是记住“哪支队以前赢”，而是验证攻防变化、市场偏差和特征规律能否跨时间复现。

线上模拟最多五天，只做工程冒烟验收：检查真实抓取、停售冻结、消息推送、页面发布和赛后结算。五天结果不得用于证明长期盈利，也不得覆盖历史盲测结论。

## 6. 四层验收标准

具体数值在数据盘点后由预先注册的评估协议确定，随后冻结，不允许为了让当前模型通过而反复修改。

### 6.1 数据有效性

- 官方赛事、奖金、让球和赛果字段完整且可追溯。
- 赛事自动映射达到预设精确率；任何歧义场次进入人工队列，不参与推荐。
- 所有特征通过 `as_of < sale_cutoff` 自动测试。
- 重复、改期、取消、时区和结算规则均有固定样例测试。
- 每个联赛和特征公布覆盖率；缺失不允许静默填补。

### 6.2 概率质量

- 与简单 Poisson、Elo、市场去水概率和“永远选热门”基线比较。
- 在滚动样本外数据上报告 Log Loss、Brier、RPS、校准曲线和 ECE。
- 正式模型必须在主要概率指标上稳定优于至少一个结构基线，且不能显著劣于市场基线。
- 玩法分层样本不足时只展示实验概率，不给正式推荐。
- 候选模型相对同一时点市场去水概率的逐场损失差，采用比赛日或轮次分块 bootstrap 计算 95% 置信区间；只有达到预先冻结的实际改善门槛才晋级。

### 6.3 盈利表现

- 使用预测当时真实可投注的官方固定奖金和官方结算规则。
- 报告投注数、命中率、净利润、ROI、最大回撤、最长连败和收益波动。
- 使用比赛日分块 bootstrap 给出 ROI 和回撤置信区间，并执行奖金恶化、安全垫和阈值敏感性测试。
- 正式推荐要求盲测期保守 ROI 为正，且收益不是由极少数高赔率事件或单一联赛贡献。
- 若置信区间无法排除无优势，只保留观察状态，不宣称模型盈利有效。
- 样本量由赔率方差和目标精度决定。实施时以约 500 个历史推荐作为初步经济评估参考、约 1000 个作为小额灰度参考；单个玩法或联赛分层少于约 200 个时不作独立盈利结论。这些是规划参考，最终门槛必须在查看盲测结果前通过功效与 bootstrap 分析冻结。

### 6.4 跨时间稳定性

- 按赛季、月份、联赛、玩法、赔率段和数据质量等级拆分。
- 大多数主要分层方向一致，不能依赖某一短窗口。
- 新模型必须在相同冻结协议下优于当前冠军模型，并满足回撤上限。
- 上线后概率校准恶化、数据覆盖下降或回撤越线时自动降级或回滚。

模型发布状态固定为：

- `RESEARCH`：概率质量门未通过。
- `PAPER_ONLY`：概率质量通过，但盈利证据不足，只生成模拟建议。
- `LIMITED_LIVE`：经济价值门通过，仅允许人工确认的小额灰度。
- `LIVE`：独立窗口继续稳定后成为正式冠军。
- `PAUSED` / `ROLLED_BACK`：数据、校准、结算或回撤触发暂停或回滚。

日报必须显示当前状态。`RESEARCH` 和 `PAPER_ONLY` 不得使用已经证明可盈利的措辞。

## 7. 每日决策与输出

每日候选依次通过：

1. 官方赛事和奖金有效。
2. 数据完整、时点合规且赛事唯一匹配。
3. 对应玩法已经通过样本外验收。
4. 保守 EV 超过玩法专属安全垫。
5. 当日、单场和相关暴露没有超限。

输出区分：

- 最稳候选：按模型命中概率排序，仅供理解，不等于值得投注。
- 价值候选：按保守 EV 和风险调整后的组合贡献排序，是正式推荐依据。
- 今日组合：从所有已验证玩法中求解当日受约束组合，默认同一比赛只保留一个正式建议。
- 不推荐：所有候选保守 EV 不为正、数据异常或模型失准时输出。

网页和报告展示模型概率、概率下界、市场去水概率、奖金及快照时间、保守 EV、主要依据、未确认信息、数据等级和对当日回撤的贡献。

## 8. 故障与安全策略

- 官方数据失败：停止推荐，只发送故障通知。
- 辅助数据缺失：扩大安全垫、降低等级或取消候选。
- 云端任务延迟：非整点多次幂等触发；支持手动补跑和本地接管。
- 已过停售时间：禁止新增或修改建议。
- 推送失败：最多三次防重复重试；飞书失败不阻止网页，本地报告始终保留。
- 密钥只存 GitHub Secrets 或本地 `.env`，不进入代码、日志、报告或公开页面。
- 默认不自动投注、不追损。资金策略即使后续启用，也仅允许小额固定单位或保守分数 Kelly，并设硬上限。
- 生产冠军模型保持冻结；挑战者只在新的独立历史窗口或冠军部署后新数据上比较。每次只改变一个可归因版本。
- 数据质量、赔率时效、特征漂移、概率校准、结算账本或最大回撤触线时，自动暂停并回滚上一冠军；禁止现场调阈值追损。

持续学习按固定节奏运行：每场赛后结算；每周监控数据、概率质量和回撤但不随意重训；每月或明确漂移触发时训练挑战者；每季度按联赛、玩法和赔率段归因并登记下一轮可验证假设。

## 12. Git 与多 Agent 协作

正式项目使用私有 GitHub 仓库。总设计师负责架构、接口、验收和集成；数据、模型、回测、前端与自动化由子 Agent 在隔离分支或 worktree 开发。合并前必须通过自动测试和交叉审查。

## 13. 主要风险

- 免费数据覆盖不完整、页面结构变化或连接不稳定。
- 历史奖金与真实可投注时点不一致造成虚假收益。
- 赛事映射、停售、改期或结算口径错误。
- 多次调参、玩法筛选和短期高 ROI 造成回测过拟合。
- 伤停和预计阵容并不等于确认缺阵。
- GitHub 调度延迟及海外运行器访问国内数据源失败。
- 公开报告涉及个人概率研究，应脱敏、避免盈利承诺，不提供代购或自动投注。

这些风险通过数据快照、时间协议、盲测、分层稳定性、置信区间、故障降级、人工兜底和本地备用运行器共同控制。

## 14. 免费持久化与发布拓扑

免费云端使用三个逻辑仓库，避免临时 GitHub Actions runner 成为事实数据源：

- 私有源码仓：代码、schema、锁文件、配置模板、评估协议和小型冠军模型包。
- 私有状态仓：压缩后的官方快照、不可修改预测账本、赛后结算、运行清单和模型注册表。只允许自动追加；更正通过新事件完成，不重写旧事件。
- 公开报告仓：只保存脱敏静态 JSON/HTML，由 EdgeOne Pages 发布；不包含资金、投注流水、内部概率明细、原始响应、Cookie、webhook 或个人标识。

状态仓按月分区，报告保留最近 90 天；完整历史在本地加密备份。状态仓达到 400 MB 或免费配额 80% 时停止新增非必要快照并告警，不自动启用付费。冠军模型包包含模型、校准器、schema、依赖锁、训练数据 manifest 和校验和，至少保留当前与上两个版本，并执行季度恢复测试。MLflow 是本地研究目录，不作为云端唯一注册表。

EdgeOne 部署失败时保留上一版本，但页面必须读取 `last_success_at`；超过 45 分钟或已跨比赛日时显示红色“数据过期”，隐藏当日建议。公开页面加 `noindex`，但不把它当访问控制。涉及个人资金的页面只在本地 Streamlit 展示。

## 15. 完全免费验收

- 不绑定信用卡，不开通自动扣费、自动扩容或付费流量包。
- GitHub Actions 私有仓按免费额度运行；额度耗尽必须停止，不得自动升级。
- EdgeOne 仅使用长期免费计划和默认域名，不购买域名，不启用中国大陆付费区。
- 飞书机器人为主通道；企业微信群机器人为微信辅助通道；若未配置企业微信才使用 Server酱，且每天最多五条。
- 任一平台配额达到 80% 时减少非关键刷新并告警；达到 95% 时停止云端非必要任务，转本地手动运行。
- 每月自动记录平台条款、配额和最后核验日期；免费条件变化时进入 `PAUSED_CLOUD`，不得产生账单。

## 16. 竞彩票型与结算引擎

玩法、单关资格、混合过关、过关方式、单注金额、奖金计算、四舍五入、让球版本、停售、延期、取消和返还规则全部由版本化 `sporttery_ruleset` 驱动，并以官方规则样例做金丝雀测试。

第一版正式经济评估只允许官方标记可单关的玩法；两串一及更高过关在联合概率、票面奖金和取消场次结算测试完成后开放。串关默认只跨不同比赛；同场不同玩法不组合。跨场概率初版按独立近似并增加相关性安全垫，后续用比赛日分组 bootstrap 压力测试。任何无法由规则引擎完整生成并重放结算的票型不得进入推荐。

票据 schema 至少包含比赛编号、玩法、选择、让球值及版本、奖金快照、过关方式、倍数、单注金额、生成时间、停售时间、规则版本和幂等键。

## 17. 资金与组合优化协议

`PAPER_ONLY` 使用 10,000 元虚拟本金、2 元为一投注单位。默认每日风险预算不超过当前本金 2%，单场不超过 0.5%，单一联赛不超过 1%，同一比赛只保留一个正式候选。仓位使用固定小单位与 1/8 Kelly 两套并行模拟，正式页面默认展示固定单位结果。

组合优化变量是每个合法票据的投注单位数；目标是在上述预算、暴露及候选上限下最大化保守预期净利润。最长连败只作验收和暂停指标，不作为优化器的直接约束。进入 `LIMITED_LIVE` 前必须由用户单独确认真实本金和硬上限；系统不得从虚拟本金推断用户可承受金额。

## 18. EV、不确定性与时间协议

概率下界初版取滚动样本外校准残差的单侧保守分位数，并按玩法、赔率区间和数据等级估计；小样本向总体收缩。安全垫分解为数据缺失、模型选择、奖金时效和相关性四项，单位统一为概率点，配置在盲测解锁前冻结，禁止同时在概率下界和安全垫中重复扣除同一风险。

所有时间以 UTC 存储、Asia/Shanghai 展示。每条输入满足：

`event_time <= retrieved_at <= prediction_created_at <= market_sale_cutoff`

其中停售时间按比赛和玩法分别保存，奖金绑定不可变 `snapshot_id`。允许的时钟误差为 60 秒；超过误差或奖金快照在发布时已超过 45 分钟，候选失效。页面、推送和票据都显示快照时间与停售时间。

没有可信历史官方竞彩时点奖金的区间，只能用于概率质量评估，不得计算或宣称中国竞彩 ROI。正式经济价值门仅使用具有可信官方奖金、让球和停售时点的样本。

## 19. 冻结评估协议与测试集治理

里程碑 1 必须先产出机器可读的 `evaluation_protocol`，在首次候选模型和 lockbox 结果暴露前签名冻结。协议明确：数据窗口、基线、主辅指标、最小实际改善、分层白名单、样本精度、ROI 置信区间、回撤预算、赔率恶化压力和模型晋级规则。

数据分为：开发 walk-forward、一次性 lockbox、上线后的 prequential 流。lockbox 只能由发布流程解锁一次；使用后即成为历史评估数据，下一代模型必须建立新的时间后移 holdout。不得反复使用同一最终赛季筛模型。

数据与结算故障触发 `PAUSED` 并停止建议；只有在数据健康且候选模型性能退化时，才回滚上一冠军。状态对应输出固定为：

- `RESEARCH`：只展示研究概率，无票据建议。
- `PAPER_ONLY`：只展示虚拟票和模拟盈亏。
- `LIMITED_LIVE`：显示需人工确认的小额候选。
- `LIVE`：显示正式候选，仍允许不下注。
- `PAUSED`、`ROLLED_BACK`、`PAUSED_CLOUD`：隐藏建议并显示原因。

## 20. 每日调度与新鲜度

北京时间 07:17 生成当日基线；10:17 至 23:47 每 30 分钟检查一次，但无受注比赛或数据无变化时快速退出。每场停售前最后一次成功快照必须不早于 45 分钟；否则该玩法不推荐。本地运行器可在用户准备投注前手动刷新。

赛后在 06:47 补抓结果并结算上一比赛日；失败时在 07:47 重试。每个运行使用 `run_id + match_id + play_type + snapshot_id` 幂等键，云端与本地同时运行时只接受时间更早且完整的唯一记录，不重复推送。GitHub 延迟或丢任务不会放宽新鲜度门槛。

## 21. 数据准入与合规注册表

每个 provider 必须登记用途、条款 URL 和版本、robots 状态、允许频率、缓存期限、是否允许公开派生结果、认证方式和停用条件。未完成审查的数据源只能人工导入研究区，不能成为生产依赖。

竞彩网采集器必须限速、缓存、带清晰 User-Agent，并保留页面变化告警和人工导入路径；“官方权威口径”不等于“已获批量抓取授权”。公开报告只展示必要派生结论和来源时间，不再分发原始内容。

## 22. 五类玩法概率边界

比分联合矩阵初始计算 0 至 10 球，并将截断外尾部概率映射到官方“胜其他、平其他、负其他”类别；总进球按官方封顶档聚合。所有玩法必须通过性质测试：概率非负、总和为 1、比分聚合与胜平负/让球/总进球一致、半全场联合分布与边际一致。

赔率去水初版使用比例归一，同时实现幂法作为敏感性比较。非互斥选项、暂停玩法、缺失奖金或异常 overround 一律不产生市场概率和推荐。
